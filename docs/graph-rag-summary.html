Graph RAG Lab Summary

2026-10-12

A hand-built graph RAG pipeline (Neo4j, two-pass extraction, entity resolution, router) answers 39.5 of 40 relational, temporal, structured and descriptive questions, against 20.5 for plain vector RAG on the same 30 documents and HR export.

Architecture

Text2Cypher and traversal read the graph; vector search reads the raw documents. The router tries them in ranked order and falls back when an answer comes back unknown.

Lessons learned

Quality came from design decisions, not from the framework: the same LLM scored 64% or 100% on extraction depending on the pipeline around it.

  1. Entity resolution decides graph quality. Every tool that skipped it (our v1, LangChain, LightRAG) split one entity into several nodes and broke multi-hop chains.

  2. Show the LLM all candidates at once. Pairwise "same entity?" judging merged 2 of 7; closed-world candidate linking merged 10 of 10 with zero wrong merges.

  3. Embeddings block, they do not decide. Alex Kim vs Alex Moore scored 0.90, the same as true matches. Calibrate thresholds on your data (0.7 guessed, 0.85 measured).

  4. Put each job in the right layer. Counting belongs in Cypher, names in extraction, history in the schema. Retrieval tricks cannot repair missing edges.

  5. One schema file feeds extraction, validation and Text2Cypher. Adding until updated query behaviour with no prompt edits.

  6. Silent failures are the norm. A dropped title field, a swallowed pipe error, a hidden subprocess crash and a 180 s hung call all looked like success until checked.

  7. Re-evaluate after every fix. Three of my fixes caused regressions; the regression gate caught them.

  8. Single runs vary by 1-2 questions. Decide on repeated runs, never on one.

  9. Noise causes confident errors. Traversal's 40-fact contexts produced invented edges and miscounts; Text2Cypher never hallucinated.

  10. Raw text is the injection surface. The graph path held; vector RAG repeated a planted false claim when it was the only source.

Architecture

Every component of the graph RAG lab in four flows; each box names the file in ~/ai-lab/graph-rag that implements it.

Ingest pipeline

Only new or changed documents reach the LLM; a deleted document takes away exactly the edges no other source supports. The batch path (stage2/resolve.py then stage1/load.py) rebuilds the same graph from scratch.

Entity resolution

Incremental ingest reuses steps 3 to 5 against entities already in the graph (ingest.py resolve_name()), so a new document never re-resolves the whole corpus.

Query path

Every LLM call on this path goes through stage1/llm.py call_json(), which picks the transport per model, applies a 30 s timeout with 2 retries, and records a trace.

Evaluation and operations

The judge is a different model from the answerer, so no model grades its own answers. The gate caught three regressions introduced by fixes during Stage 2.
